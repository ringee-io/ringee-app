# Dialer SDK — Live Playground (real)

A **real, deployable** playground that drives the *production* SDK bundle
(`window.Ringee`, the exact IIFE shipped to unpkg/jsDelivr) against a **real
Ringee backend**. It covers all three integration modes — **Floating**, **Bar**
and **Headless** — places real WebRTC calls, and is fully runtime-configurable,
so the same static build works **locally** and **in production** with no rebuild.

> This is the real thing (network, OTP, WebRTC, credit). For frozen visual
> states with no backend, use the sibling `../ui-gallery` (mock).

## What it does

- Loads the same `ringee.global.js` a CDN consumer loads — `Ringee.createFloating`,
  `Ringee.createBar`, `Ringee.create` (headless).
- A **config panel**: publishable key, API base URL, agent email, mode, locale,
  theme, Hold, debug — persisted in `localStorage`, shareable via URL, and
  overridable by build-time env defaults.
- Contact injection (`setContact` / `prefill` / `startCall`) and a live event log.

## Run locally

```bash
# From the repo root — builds the SDK (if needed), copies the bundle into
# ./vendor, and serves the folder on http://localhost:5173
node apps/sdk-playground/live/build.mjs --serve
```

Then, with the Ringee backend running (`pnpm dev:backend`, API on `:3000`):

1. Open <http://localhost:5173>.
2. Make sure your publishable key's `allowedOrigins` includes
   **`http://localhost:5173`** (the server prints this reminder).
3. Paste your `pk_live_…`, set **API base URL** to `http://localhost:3000`,
   pick a mode, and click **Montar / Aplicar**.

The panel auto-mounts when a key is already present (shared link or env default).

### Flags

| Command | Effect |
| --- | --- |
| `node build.mjs` | Copy the SDK bundle → `vendor/` (builds it if missing). |
| `node build.mjs --build` | Force-rebuild the SDK first, then copy. |
| `node build.mjs --serve` | Build, then serve on `:5173` (`PORT=… ` to change). |

Rebuild the SDK and re-copy after changing SDK source:
`node apps/sdk-playground/live/build.mjs --build`.

## Get a publishable key

The key is minted by an **org-admin** session (never from the public frontend):

```http
POST /api/integrations/custom
{ "name": "Playground" }

POST /api/integrations/custom/<integrationId>/publishable-keys
{ "allowedOrigins": ["http://localhost:5173", "https://<your-playground-host>"] }
```

Origins are matched **exactly** (protocol + host + port). Add every origin the
playground is served from.

## Deploy to production

The `live/` folder is a **self-contained static site** after `build.mjs` runs —
deploy it to any static host (Vercel, Netlify, Cloudflare Pages, S3+CloudFront,
nginx). Two ways to configure it:

**A) Zero-config (recommended):** deploy as-is and let each visitor paste the key
in the panel (a `pk_live_…` is browser-safe — security is the origin allow-list +
OTP, not key secrecy). The API URL defaults to `https://api.ringee.io`; change it
in the panel.

**B) Baked defaults:** set env vars in your build step so the deployed page comes
pre-filled and auto-mounts:

```bash
RINGEE_PLAYGROUND_PK="pk_live_xxxxx" \
RINGEE_PLAYGROUND_API="https://api.yourdomain.com" \
RINGEE_PLAYGROUND_LOCALE="es" \
node apps/sdk-playground/live/build.mjs
# then publish apps/sdk-playground/live/  (vendor/ is generated by this step)
```

Whatever origin you deploy to (e.g. `https://playground.ringee.io`) **must** be
in the publishable key's `allowedOrigins`, and production must be served over
**HTTPS** (required for the microphone).

Example (Vercel): set the project root to `apps/sdk-playground/live`, build
command `node build.mjs` (run from the repo so pnpm can build the SDK), output
directory `.`.

## Share a preconfigured link

The **Copiar enlace** button encodes the current config as query params
(`?pk=…&api=…&mode=…&to=…`). Opening that URL auto-mounts — handy for demos.
Anything in the URL overrides `localStorage`.

| File | What |

## Troubleshooting

- **`DOMAIN_NOT_ALLOWED`** — the served origin isn't in `allowedOrigins`. Check
  the "origen actual" line in the panel and match it exactly.
- **`INVALID_PUBLISHABLE_KEY`** — wrong/rotated key; mint a new one.
- **`MICROPHONE_DENIED`** — serve over HTTPS (or `localhost`) and allow the mic.
- **SDK not loaded** — run `node build.mjs` so `vendor/ringee.global.js` exists.
